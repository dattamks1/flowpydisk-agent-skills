# FlowpyDisk agent guides

One guide per surface of the product, for models and agents that reach FlowpyDisk over MCP. Start with [the skill](../SKILL.md), then read the guide for the surface you are working on. The server serves the same text with `get_guide("<topic>")`, and `get_guide()` lists every topic.

## How these guides are written

1. **For a model with no screen.** "It looks wrong" is not usable. "A text card
   with no `fill_color` renders in the board's card tone, which is the sticky
   yellow" is.
2. **Judgement first, parameters second.** The schema already carries the
   parameters. A guide earns its place by saying which of them matter, in what
   combination, and what good output looks like.
3. **Every trap in it has been hit.** These are field notes, not advice invented
   in advance. A guessed rule is worse than no rule: it is confidently wrong, at
   scale, in a document that claims authority.

## One thing these guides do not do

They do not argue with the connector's limits. Publishing, sharing with a
person, opening a form to the public, share links and permanent deletion are
**deliberately unreachable** over a connected app, because they make content
public or grant access to other people and that is a person's decision in the
web app. A guide says so and points there. It does not call it a gap.
